- Official SPLART implementation is vendored under `method/splart_upstream`.
- A lightweight reproduction in `method/lightweight_splart.py` implements the paper's identifiable core computations: differentiable per-Gaussian mobility, weighted Chamfer, cross-static mobility fitting, and cross-mobile articulation fitting/refinement.
- `eval/` is method-agnostic and reads output artifacts only.
- `baseline/static_alignment.py` provides a static-object baseline.

## Issues

- The full SPLART code depends on Nerfstudio, gsplat, PyTorch3D, tiny-cuda-nn, and CUDA extension builds. To get an initial reproducible benchmark quickly, the first job uses a lightweight Gaussian benchmark instead of the full image-rendering pipeline.
- Local login-node Python lacks NumPy, so only syntax validation and repository validation were run locally. Package installation is handled through `environment/setup.sh`.

## Deviations from Paper

- Paper data: PARIS-PMS and SPLART-PMS posed RGB datasets with full 3DGS photometric optimization. Substitute: a small procedural two-state articulated Gaussian benchmark generated by `data/articulated_gaussians.py`. Reason: the first iteration needs an end-to-end, no-download smoke benchmark that preserves the two-state articulation and mobility-estimation problem.
- Paper rendering stages: full photometric 3DGS rendering losses. Substitute: weighted Chamfer losses over Gaussian means for the first job. Reason: this preserves the paper's core cross-static/cross-mobile computation while avoiding CUDA-extension build risk for the first validation job. The official full implementation remains vendored for later expansion.
